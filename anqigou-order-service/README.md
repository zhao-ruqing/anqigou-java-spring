# anqigou-order-service

订单服务，端口 `8083`。简单说就是管"买东西"这件事的：选商品加购物车 → 下单 → 付钱 → 发货 → 收货 → 不满意就售后。

## 技术栈

Spring Boot + MyBatis-Plus + MySQL + Druid + Redis + Nacos + OpenFeign + RabbitMQ + Lombok

## 文件夹都干了啥

```
com/anqigou/order/
│
├── controller/      控制器 —— 门面，接 HTTP 请求的
│                    前端/其他服务发请求过来，controller 负责接住，
│                    校验一下参数对不对，然后丢给 service 去处理，
│                    最后把结果返回给调用方。自己不写业务逻辑。
│
├── service/         业务层 —— 真正干活的地方
│   └── impl/        上面是接口，这里是具体实现
│                    比如"下单"要做哪些事？先查地址、再查库存、
│                    算钱、扣库存、清购物车，这一整套流程都在这写。
│
├── entity/          实体类 —— 数据库表和 Java 类的对应关系
│                    数据库里有个 orders 表，这里就有一个 Order 类，
│                    字段一一对上。MyBatis-Plus 靠它知道怎么读写数据。
│
├── dto/             数据传递用的临时对象
│                    比如前端下单时传过来的 JSON，需要一个对象装着；
│                    返回订单详情给前端，字段跟 entity 不完全一样，
│                    也得单独建个对象。这些"传话用的"对象就是 dto。
│
├── mapper/          数据库操作 —— 增删改查
│                    继承 MyBatis-Plus 的 BaseMapper，自带单表增删改查，
│                    不需要手写 SQL。复杂查询才单独写。
│
├── client/          远程调用 —— 找别的服务帮忙
│                    Feign 客户端，订单服务自己搞不定的事就找别人：
│                    要商品信息 → 找商品服务
│                    要收货地址 → 找用户服务
│                    要发货     → 找物流服务
│
└── listener/        消息监听 —— 等别人通知
│                    比如"支付成功了"这个事件发到 RabbitMQ，
│                    这里收到消息后做后续处理（目前还是预留的，没写完）。
```

## 一条订单的一生

```
加购物车 → 下单(验库存、算钱、扣库存) → 支付 → 商家发货 → 用户收货 → 完成
                                                          ↓
                                                    有问题？→ 申请售后 → 退货退款
```

## 注意

金额全用**分**存（Long 类型），比如 100 就是 1 块钱，避免小数精度问题。
